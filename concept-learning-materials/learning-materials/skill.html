Concept Learning Card

Skill（技能 / Agent Skill）

把"某类任务的专业知识"打包成文件夹（核心是 SKILL.md），让 AI 在相关时被按需加载、自动使用——是可复用的任务知识，而不是一次性提示词。

生成日期：2026-09-06 · 学习视角：AI Agent 工程入门 · 资料来源均为公开可核查链接

01学习目标

  • 能说清 Skill 由什么组成，以及它和"一段提示词（Prompt）"的本质区别。
  • 理解 Skill 的"三级渐进式披露"机制，以及它为何几乎不占上下文。
  • 能举出 Skill 在真实工作流里"沉淀可复用知识"的具体例子。

02核心问题

  • Skill 到底是个文件，还是个功能？它放在哪里、怎么被触发？
  • 装很多 Skill 会不会把上下文撑爆？为什么通常不会？
  • Skill、Prompt、Workflow、Agent 这四者各自的边界在哪？

03个人解释

我的理解：

我之前把"提示词"当成万能钥匙——每次新任务都重新写一大段。学完 Skill 后我明白：Skill 更像给 AI 写的"岗位说明书 / 入职手册"。你把一个任务的经验（步骤、注意事项、模板、甚至脚本）固化成一个文件夹，以后只要任务相关，AI 就自动翻出来用，不用你每次重说一遍。

我们这次作业本身就是最好例子：我建的 concept-learning-generator 这个 Skill，把"如何生成概念学习资料"的知识沉淀下来，于是学 Agent、学上下文、学 Skill 自己，都只要说一句"用这个 Skill 学 XXX"就行。Skill 的精髓就是"一次编写，跨会话、跨概念复用"。

对我这个还在打编程基础的大二学生来说，Skill 最打动我的是"把经验留下来"。以前遇到同类任务就重新搜教程、重复试错；现在哪怕只是一个小方法论，也能写成 SKILL.md 沉淀进仓库、还能版本管理。这次作业本身就是一次示范：我用自己写的 Skill 一口气生成了三份资料，确实比每次从零写提示词省力。算是提前体验了一把"建自己的工具箱"。——杨国美

04核心机制 / 组成

① Skill 是一个目录，核心是一个 SKILL.md。按照 Anthropic 提出的 Agent Skills 开放标准，一个 Skill 至少包含：

  • SKILL.md：YAML 元数据（name + description）+ 正文指令（流程、最佳实践）。description 是模型判断"何时启用本 Skill"的依据，所以要写清"做什么 + 何时用"。
  • 可选资源：额外 Markdown（如 FORMS.md）、可执行脚本（如 fill_form.py）、模板或参考文档。

② 三级渐进式披露（Progressive Disclosure）——这是它"省上下文"的关键 [来源 2]：

层级何时加载内容上下文代价
L1 元数据启动时常驻name + description（YAML）约 100 token / 个
L2 指令被命中触发时SKILL.md 正文通常 < 5k token
L3 资源/代码按需读取脚本、参考文档、模板用到才进上下文

所以"装很多 Skill"并不可怕：未触发时，只占 name+description 那一点点元数据；只有相关时，正文才被读入上下文。

③ Skill 与 Prompt 的区别：Prompt 是对话级、一次性的指令；Skill 是文件系统级、可复用、按需加载的资源，把通用智能体变成某领域的专家，且无需在不同对话里重复相同指导 [来源 2][来源 3]。

④ 在本仓库里的落地：项目级 Skill 位于 .workbuddy/skills/concept-learning-generator/SKILL.md。WorkBuddy 采用的正是上述"SKILL.md + 元数据 + 渐进披露"的同一思路。

05应用场景（具体例子）

场景：团队要反复做"把概念变成带来源的学习卡片"。

  • 没有 Skill 时：每次都要在对话里重写一整套要求（结构、来源规范、风格），又长又容易漏，且换个人/换个会话就失效。
  • 有了 Skill 后：把"学习目标 → 个人解释 → 机制 → 场景 → 边界 → 自测 → 来源"这套方法论写成 SKILL.md。之后任何人只要说"用 concept-learning-generator 学 RAG"，AI 就自动按规范产出，且所有资料风格统一、来源可核查。
  • 沉淀价值：知识留在仓库里、进版本管理、可分享给同学；这正是 Skill "把任务知识固化下来"的意义。

06易混淆 / 使用边界

① Skill ≠ Prompt。Prompt 一次性；Skill 跨会话复用、按需触发。需要"经常重复同一套方法论"时才值得做成 Skill。

② Skill ≠ Agent。Skill 不自己跑"思考-行动"循环；它只是在 Agent 需要时，把专业知识"喂"给 Agent。Agent 决定调用，Skill 提供能力。

③ Skill 可以包含可执行代码。这正是它强于纯提示的地方（用代码做确定性强的事，比让模型"生成 token 来做"更可靠）。但也意味着：只从可信来源安装 Skill，因为它可能执行代码 [来源 1]。

④ description 写不好 = Skill 永不触发。模型靠 description 匹配任务，务必写清"做什么 + 何时用"，否则沉淀的知识等于白写。

07自测问题

Q1：一个 Skill 目录里最核心的文件是什么？它必须包含哪两类内容？
答：最核心是 SKILL.md，必须包含 YAML 元数据（至少 name 与 description）和正文指令（流程/最佳实践）。
Q2：为什么"安装很多 Skill"通常不会撑爆上下文？
答：因为渐进式披露：未触发时只加载 name+description 的少量元数据（约 100 token/个），只有命中相关任务时正文才被读入，资源/代码更只是用到才加载。
Q3：Skill 与 Prompt 最本质的区别是什么？
答：Prompt 是一次性、对话级的指令；Skill 是可复用、文件系统级、按需加载的知识包，跨会话生效，无需重复书写相同指导。
Q4：Skill 自己会主动去调用工具、跑循环吗？
答：不会。Skill 本身不决策、不循环；它只是"被 Agent 在相关时加载进来"的专业知识/能力。是否使用由 Agent 决定。
Q5（选择题·概念辨析）：下列关于 Skill 与 Prompt 的说法，哪一项最准确？
答：正确答案 B。Prompt 是一次性、对话级的指令；Skill 是可复用、文件系统级、按需加载的知识包。A 错在"Skill 只是更长的提示词"；C 错在"Prompt 更强"；D 错在二者本质不同。
Q6（选择题·风险边界）：关于"从何处安装 Skill"，下列说法正确的是？
答：正确答案 B。Skill 目录里可能包含可执行脚本，所以应只从可信来源安装，避免运行不可信代码。A 错在"随便装"；C 错在"绝不会执行代码"；D 错在"装越多越安全"（渐进披露虽省上下文，但不可信代码有安全风险）。
Q7（应用题）：你的团队每周都要把一篇英文论文整理成"中文要点笔记"。请用本资料中的 Skill 思路，说明如何避免每周重写提示词，并列出 SKILL.md 至少要写清什么。
答题要点：①把"读论文→提取要点→中英对照→形成笔记"的方法论固化成 SKILL.md（含 name+description+正文流程）；②description 写清"做什么+何时用"，例如"当需要把英文论文转成中文要点笔记时使用"；③之后任何人/任何会话只要说"用这个 Skill 处理这篇论文"即可复用，无需重说；④知识进版本库、可分享、可迭代。
Q8（应用题）：你写了一个 Skill，但 Agent 从没自动启用它。结合资料，给出最可能的 2 个原因与排查方向。
答题要点：①description 没写清"做什么+何时用"，模型无法把任务匹配到它→重写 description，补全场景关键词；②Skill 没放在 Agent 可发现的目录（如项目级 .workbuddy/skills/）→确认目录位置；③触发词与 description 不符→在 description 补充同义词/示例。
