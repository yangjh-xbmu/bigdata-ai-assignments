Concept Relationship

Agent、大模型的上下文、Skill 三者关系

Skill 给 Agent 提供"能力"，Agent 在"上下文"这个有限舞台上调用能力与工具完成任务。

生成日期：2026-09-06 · 配套说明见仓库根目录 concept-relationship.md

A一句话总览

  • Agent：干活的智能体，靠"思考 → 行动 → 观察"循环完成任务。
  • 上下文 Context：Agent 每一步"能看到的工作台"，有限且会衰减的资源。
  • Skill：把某类任务的专业知识固化下来的文件包，相关时自动加载、变专家。

B上下文如何影响 Agent

Agent 的自主循环会把系统指令、工具定义、每一步工具返回、历史、检索资料全部堆进上下文窗口，因此上下文直接决定 Agent 的能力边界：

上下文状态对 Agent 的影响
窗口足够、信息精选Agent 持续"记得目标、用对工具"，长任务跑得动
信息过多未管理context rot（越长越准度下降）、Lost in the Middle（中段被忽略）
超出窗口上限必须压缩/外置/摘要，否则停止或报错
错误/幻觉进入上下文Context Poisoning，错误被反复复用放大

没有好的上下文工程，Agent 越自主越容易"跑偏、变笨、忘事"。

CSkill 如何沉淀可复用知识

  • 把某类任务的专业知识（步骤/注意事项/模板/脚本）固化成目录，核心是 SKILL.md（name + description 元数据 + 正文指令）。
  • 三级渐进式披露：未触发只占约 100 token 元数据，命中才读正文，脚本/参考用到才加载——几乎不浪费上下文。
  • 知识从"某次对话的提示词"变成"仓库里、可版本化、可分享"的资产，跨会话复用。
  • 本仓库的 concept-learning-generator 即此沉淀：学 Agent / 上下文 / Skill 自己，都只需一句"用这个 Skill 学 XXX"。

flowchart LR
    S[Skill 可复用任务知识] -->|按需加载 提供专业指令/脚本| A[Agent 自主循环 思考-行动-观察]
    A -->|每一步推理都发生在| C[上下文窗口 有限且会衰减]
    C -->|context rot / Lost in Middle 需压缩·外置·检索| A
    A -->|调用外部工具/API| T[(环境/工具)]

    S -.->|渐进披露 省上下文| C

若上方图示未渲染（例如离线打开），请见下方文字说明。

图例解读：

① Skill → Agent：任务相关时加载，赋予 Agent 特定领域专业知识与流程。

② Agent → 上下文：所有推理、工具调用、历史都发生在上下文窗口中，窗口直接约束 Agent。

③ 上下文 ↔ Agent（回环）：上下文腐化拖垮 Agent，故 Agent 需"上下文工程"反向治理。

④ Agent → 工具 → 上下文：工具结果回到上下文，既是"观察"也是下一轮输入，形成闭环。

⑤ Skill ⇢ 上下文：Skill 靠渐进式披露，只在必要时占用上下文，避免"装一堆就爆窗"。

E个人判断（重点）

  • 上下文是 Agent 的"物理限制"，Skill 是 Agent 的"能力扩展"。一个决定"能不能跑稳"，一个决定"能不能变专业"，缺一不可。
  • 真正让 Agent 可用的，往往不是模型多大，而是上下文工程做得多好。"长任务忘事、跑偏"的根因几乎都在上下文。
  • Skill 的价值在于"把经验变成资产"。可复用、可审查、可进版本库——这也是本仓库存在的意义。
