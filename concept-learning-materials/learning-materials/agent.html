Agent（智能体 / 代理）

以大模型（LLM）为"大脑"、能自主规划并使用工具去完成开放任务的系统。

03个人解释

我的理解：

我以前以为"Agent"就是"会聊天的 AI"。学完之后我认为它更像一个能自己想办法干活的小员工：你给它一个目标，它自己拆步骤、自己决定查资料还是跑代码、自己看结果对不对，不行就重来。关键不是"它多能聊"，而是它有一个"思考 → 行动 → 观察 → 再思考"的循环，而且这个循环里它会真的去调用外部工具（搜索、执行代码、访问 API），而不是只在脑子里编答案。

另一个让我改观的点：Agent 不一定越复杂越好。Anthropic 那篇《Building Effective Agents》反复强调——先用最简单可行的方案，只在必要时才加复杂性。这跟我直觉相反，但很实用。

作为大二学生，这学期是我第一次系统接触 AI Agent 工程。最大的触动是：以前写程序是"人定流程、机器执行"，而 Agent 反过来——人给目标、机器定流程。这刷新了我对"编程"的理解。以后做课程项目，我可能会先写一个简单 Workflow 试试水，而不是一上来就追求"全自动 Agent"。——杨国美

04核心机制 / 组成

从工程视角，一个 Agent 系统通常建立在三个基础能力之上（参考 Lilian Weng 对 Agent 架构的拆解与 Anthropic 的实践总结）：

核心能力它做什么典型实现
规划 Planning把大任务拆成子目标；必要时自我反思、纠正错误路径Chain-of-Thought、Tree-of-Thought、ReAct、Reflexion
记忆 Memory短期记忆 = 当前上下文；长期记忆 = 外部可检索存储向量数据库（MIPS）、对话历史压缩
工具使用 Tool Use调用外部 API / 代码执行 / 检索，补足模型权重里没有的信息函数调用、MCP、搜索/代码解释器

Anthropic 进一步把"带 LLM 的系统"分成三层的光谱（从简到繁）：

  • 增强型 LLM：在 LLM 上挂检索、工具、记忆，但流程是写死的。
  • 工作流 Workflow：用代码预定义控制流（提示链、路由、并行、编排-工人、评估-优化 五种常见模式），每一步可控、可调试。
  • Agent（自主循环）：LLM 自己掌控控制流——自己规划、调工具、看结果，直到满足停止条件。适合"步骤数无法预先预测"的开放任务。

Agent 自主循环（Thought → Action → Observation → …）

目标 → [思考] → [选工具/行动] → [环境返回观察] → 回到思考 → 直到停止条件

一句话记忆法：Workflow = 人写流程让 LLM 填空；Agent = LLM 自己写流程。

05应用场景（具体例子）

场景：一个"代码库调研 Agent"帮助新同事快速理解陌生项目。

  • 谁用：刚接手项目的开发工程师。
  • 什么环节：他需要搞懂"支付模块是怎么串起来的"，但项目有 300 个文件。
  • Agent 怎么做：规划 → 先搜索关键词定位入口文件 → 读文件（工具）→ 观察依赖 → 再追下一个调用 → 自我反思"还差哪条链路" → 最终生成一份带文件引用的调用关系说明。
  • 解决了什么：把"人肉翻 300 个文件"变成"几分钟的可追溯调研"，且每一步都来自真实工具返回，而不是模型凭记忆编的。

06易混淆 / 使用边界

① Agent ≠ Workflow。Workflow 的控制流是代码写死的；Agent 的控制流由 LLM 在运行时决定。很多需求其实用 Workflow 就够了，别一上来就上 Agent。

② 自主性有代价。越自主 = 越高成本 + 越高"错误累积"风险（每多一次 LLM 调用都可能引入新错）。Anthropic 明确提醒：Agent 的自主性意味着更高的成本与复合错误可能性。

③ 不是所有任务都适合。步骤可预测、追求稳定可调试的任务，用 Workflow 更稳；只有"路径不可预知"的开放任务才值得用 Agent。

④ 上下文会"腐化"。长循环会产生海量上下文，超过窗口或导致"上下文腐化（context rot）"，需要压缩/外置记忆（详见《大模型的上下文》卡片）。

应用题 1（动手做）：让你设计一个"简历初筛 Agent"，读取 100 份简历 PDF 并挑出符合岗位要求的候选人。请结合本资料，列出你会怎么用"上下文工程"避免它跑着跑着变笨/忘事。
答题要点：① Offload——把 100 份 PDF 外置到文件，只把"当前正在看的那份的关键字段"放进上下文；② Reduce——定期把已处理进度压缩成"已看 N 份/已筛出 M 份"的摘要；③ 把"岗位要求清单"写在上下文首尾，对抗 Lost in the Middle；④ 设步数/预算上限与人工兜底，防止循环失控与成本爆炸；⑤ 简历筛选步骤相对可预测，可用 Workflow（固定流程）而非完全自主 Agent。
应用题 2（辨析）：有人说"Agent 就是比普通聊天机器人聪明"。你会怎么纠正这句话？请用自己的话说明 Agent 真正的本质。
答题要点：聪明与否取决于底层模型；Agent 的本质是"自主性 + 工具调用 + 观察闭环"：人给目标，它自己规划步骤、调用工具、看结果、再决定下一步，直到满足停止条件。普通聊天机器人多为一次性问答，不真的去执行动作或观察环境。所以 Agent 强在"能干活/闭环"，不是"更聪明"。
